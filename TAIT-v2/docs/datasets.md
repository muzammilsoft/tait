# Datasets

TAIT 2.1 supports compact instruction datasets with an optional reasoning trace. JSONL is intentionally simple so datasets can be generated by a human or by another language model.

## Recommended schema

Each line is one JSON object:

```json
{"prompt":"شنو عاصمة السودان؟","reasoning":"السؤال عن عاصمة السودان، والمدينة المعروفة بأنها العاصمة هي الخرطوم.","response":"عاصمة السودان هي الخرطوم."}
```

Required fields:

- `prompt`: the user's question/instruction.
- `response`: the final useful answer.

Optional field:

- `reasoning`: a short, task-relevant reasoning trace. TAIT also accepts `cot`, `chain_of_thought`, `thought`, or `thinking` for this field.

The existing aliases remain supported:

- prompt: `prompt`, `question`, `input`
- response: `response`, `answer`, `output`

## What makes a good TAIT dataset?

The goal is **useful sentence formation and instruction following**, not random conversation memorization.

Prefer examples that:

1. Have a clear question/instruction and a clear answer.
2. Use complete, natural sentences.
3. Vary the wording of similar requests.
4. Keep the reasoning short and relevant to the answer.
5. Avoid unrelated chatter, broken sentences, IDs, timestamps, or scraped noise.
6. Avoid contradictory answers unless the prompt explicitly asks for alternatives.
7. Include both simple and slightly more complex questions.
8. For a dialect model, keep the target dialect consistent.
9. For multilingual training, label or balance languages deliberately rather than mixing random noise.
10. Do not put the final answer only inside reasoning; always provide a separate `response`.

### Good reasoning

```json
{"prompt":"12 + 8 كم؟","reasoning":"نجمع 12 و8، والناتج 20.","response":"20."}
```

### Poor reasoning

```json
{"prompt":"12 + 8 كم؟","reasoning":"Maybe numbers are interesting and I remember many things...","response":"20."}
```

The second example teaches irrelevant text and wastes the capacity of a tiny model.

## Generate datasets with another AI

Give the generator these rules:

> Generate JSONL instruction examples for TAIT. Each line must be valid JSON with `prompt`, `reasoning`, and `response`. Make the prompt natural and specific. Make reasoning short, factual, and directly connected to the answer. Make the response concise, useful, and complete. Do not add IDs, metadata, markdown fences, commentary, or duplicate examples. Keep the requested language/dialect consistent. Create varied questions that test explanation, comparison, classification, simple reasoning, and practical help. Never invent facts when the prompt does not provide enough information; instead make the response state the limitation.

For Sudanese Arabic, add:

> Write natural Sudanese colloquial Arabic. Prefer real Sudanese usage such as `زول`, `شنو`, `داير`, `ياخي`, `برضو`, `عشان`, `لكن`, `أها` when natural. Do not turn every example into a forced dialect showcase.

## Included samples

- `examples/datasets/arabic.jsonl` — Arabic examples.
- `examples/datasets/english.jsonl` — English examples.
- `examples/datasets/mixed.jsonl` — mixed Arabic/English examples; this is the default training dataset.

Inspect them with:

```bash
tait data inspect examples/datasets/mixed.jsonl -n 5
tait data validate examples/datasets/mixed.jsonl --strict
```

## Training behavior

TAIT 2.1 can train with **response-only loss**. Prompt tokens are used as context, but loss is focused on the target side after `SEP`. This is enabled by default because it better matches the chat objective.

When reasoning is enabled, examples with a reasoning field are serialized as:

```text
prompt <SEP> <think>reasoning</think><answer>response</answer> <END>
```

Examples without reasoning still receive an `<answer>...</answer>` target, so a dataset can be migrated gradually.
